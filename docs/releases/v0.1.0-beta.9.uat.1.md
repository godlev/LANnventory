# LANnventory v0.1.0-beta.9.uat.1

## Summary

This is the Phase 35.9 UAT build for safe scheduled Proxmox API inventory synchronization.

- Adds per-Proxmox-host Automatic Sync with 15 minute, 30 minute, 1 hour, 6 hour, 12 hour, and 24 hour intervals.
- Keeps Automatic Sync off by default and preserves the existing manual Sync now → Preview/Diff → explicit Apply workflow.
- Uses one shared Proxmox sync engine for manual and automatic collection instead of maintaining separate import logic.
- Automatically applies only complete, valid snapshots that pass the existing matching and conflict safety rules.
- Records Last Attempt, Last Successful Collection, Last Applied, Next Sync, trigger, status, and actionable error/review state separately.
- Shows Review required when a valid collection cannot be applied safely, with the normal Sync now preview workflow available for review.
- Preserves last-good inventory on authentication, TLS, timeout, incomplete-collection, validation, conflict, and stale-configuration failures.
- Prevents failed or partial automatic runs from retiring workloads; complete trusted snapshots may still retire genuinely removed managed workloads.
- Adds a centralized context-aware scheduler with bounded concurrency, deterministic startup behavior, same-host exclusion, live configuration reloading, stale-result protection, clean shutdown, and restart persistence.
- Keeps Proxmox API credentials write-only and does not add VM/LXC control operations.

## UAT focus

Upgrade from `v0.1.0-beta.9` through **Settings → Updates** on the **Beta** channel.

On the Proxmox host page verify:

1. Existing Proxmox API configuration and stored token remain intact.
2. Automatic Sync is initially **Off** after upgrade.
3. Enable Automatic Sync and select **15 minutes** for the test.
4. Save and verify a future **Next sync** is shown; enabling scheduling must not trigger an immediate run.
5. Wait for the scheduled run and verify **Last attempt**, **Last successful collection**, and **Last applied** update independently and Status becomes **Healthy**.
6. If practical, make a harmless detectable inventory change in Proxmox and confirm the next safe automatic run applies it.
7. Disable Automatic Sync and confirm no further scheduled runs occur.
8. Re-enable it and change the interval; verify **Next sync** is recalculated.
9. Verify manual **Sync now** still produces Preview/Diff and still requires explicit Apply.
10. Temporarily make Proxmox unavailable or otherwise force a safe connection failure; verify the previous inventory and Last Applied state remain intact.
11. Restore connectivity and confirm a later sync recovers cleanly.
12. If a harmless conflict/review scenario can be reproduced, verify Status becomes **Review required**, Last Successful Collection advances, Last Applied does not, and Sync now opens the normal review path.
13. Restart LANnventory and verify Automatic Sync/interval configuration persists and scheduling resumes without an immediate sync storm.
14. Verify no Proxmox start/stop/reboot/control actions were introduced.

## Automated hardening included

The UAT candidate includes regression coverage for disabled scheduling, interval changes, shutdown cancellation, bounded concurrency, same-host manual/automatic exclusion, authentication/TLS/timeout failures, incomplete snapshots, matching conflicts, safe retirement, stale in-flight configuration, host deletion, database restart persistence, and updater SemVer ordering.
