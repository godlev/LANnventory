# LANnventory v0.1.0-beta.7

## Summary

- Adds generic, network, system and hypervisor device profiles without changing the existing exclusive Device Type model.
- Adds first-class infrastructure workload inventory for VM and LXC/container guests, including persisted workload interfaces, lifecycle state and workload-to-Host relationships.
- Adds a safe read-only Proxmox VE collector workflow with JSON snapshot validation, preview/diff and explicit import/apply semantics. The collector does not create, start, stop, modify or delete Proxmox guests.
- Adds conservative workload matching: exact MAC is the only deterministic automatic link path; address/name evidence remains reviewable, and manual links remain protected.
- Adds **Possible IP conflict** handling for current address overlap with contradictory MAC evidence, with side-by-side evidence, **Link anyway** and persistent **Not this Host** decisions.
- Retained historical IP reuse remains visible as identity/history context but no longer acts as workload-match evidence.
- Adds dedicated Proxmox Host inventory UI plus reverse guest ancestry on linked LANnventory Hosts.
- Home shows linked guest VM/LXC markers and Proxmox hypervisor VM/LXC totals from the full current non-retired imported workload inventory.
- Adds **Comfortable** and persistent **Compact** Home table modes; Compact keeps each desktop device row on one line and compresses Proxmox guest metadata to an icon plus VMID/CTID.
- Hardens Proxmox/Home identity mapping across canonical and stored MAC representations, including lowercase discovered Host MACs.

## Safety and data model

- Phase 35 remains local-first and credential-free: Proxmox data enters through an explicit read-only snapshot import.
- Imported/discovered integration data stays separate from manually managed Host/profile fields.
- Workload rejection decisions are non-destructive and do not merge Host identities or erase retained address history.
- Retired workloads remain historical records but are excluded from active Home inventory totals.

## Upgrade and migration

- Database changes are additive.
- Existing Host identity, Events, Presence, Services and managed metadata remain compatible.
- Beta-channel updater selection is regression-tested from beta.6 and representative Phase 35 UAT releases through beta.6.uat.9.

## Validation

- Phase 35 UAT covered collector onboarding, snapshot validation/preview, matching, IP-conflict handling, reverse Proxmox ancestry, Home Comfortable/Compact modes and current workload totals.
- Frontend semantic checks, embedded bundle verification, Swagger freshness, backend tests, race detector, go vet, backend build, Docker/Compose smoke tests and GoReleaser artifact dry-run are required before final publication.
- Proxmox API credentials and automatic synchronization are intentionally deferred to the next Phase 35.8 work and are not part of beta.7.
