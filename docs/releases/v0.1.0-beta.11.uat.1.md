# LANnventory v0.1.0-beta.11.uat.1

## Summary

This UAT build introduces **Phase 35.11 — Unknown Device Identification Toolkit** on top of `v0.1.0-beta.11`.

The goal is to help identify Unknown devices from evidence LANnventory already retains, while keeping every active investigation explicit, bounded and reviewable. The workflow does not automatically probe a device when the helper is opened and does not automatically change managed identity fields or Known state.

## Retained-evidence assessment

- Adds a Host-level **Help identify** workflow for Unknown devices.
- Aggregates retained discovery, service, address-history and exact workload-interface evidence.
- Separates **current, stale and historical** evidence so old observations do not look current.
- Uses explainable confidence levels and exposes reasons, cautions and conflicts.
- Treats an exact current workload interface MAC match as strong infrastructure evidence.
- Does not treat workload membership alone as identity proof.
- Does not invent a device type from generic web/SSH ports or vendor information alone.
- Deduplicates matching reverse-DNS and system-resolver hostname clues.
- Warns when the current IP has retained reuse by other identities without exposing those identities in the identification response.

## Explainable suggestions

- Can suggest a managed **Name** and/or **Device type** when retained evidence is strong enough.
- Shows confidence and provenance for suggested values.
- **Use name**, **Use device type** and **Use both** only populate the existing managed edit draft.
- Suggestions never save automatically and never mark a device Known automatically.

## Explicit investigation toolkit

- Adds targeted **Refresh names** using only reverse DNS, the system resolver and Avahi/mDNS hostname resolution.
- Does not invoke SSDP during targeted name refresh.
- Does not change Presence, LastSeen or managed inventory while refreshing identification evidence.
- Discloses that reverse DNS follows the configured resolver and may be forwarded by that resolver.
- Adds bounded sequential TCP presets:
  - Common: 22, 80, 443, 445, 554, 631, 8080, 8443, 9100
  - Camera / IoT: 80, 443, 554, 8000, 8080, 8554
  - Printer: 80, 443, 515, 631, 9100
- Preset probes reuse the existing Host-bound per-port scan path rather than arbitrary-address probing.
- A running investigation can be stopped and completed partial results can refresh the retained assessment.
- Existing **Services** and **Identity history** remain the detailed investigation destinations.

## Persistence and safety

- Port and hostname probe results are revalidated against the Host ID, normalized MAC and current IP before persistence.
- Results are rejected if the Host binding changes while the probe is running.
- Retained evidence returned by the identification endpoint is bounded.
- Name refresh only writes evidence for hostname sources that actually returned values; omitted or timed-out sources are not falsely invalidated.
- No new database schema or migration is introduced.

## Save and mark Known

- Adds an explicit **Save and mark Known** action while editing an Unknown device.
- Uses the existing atomic `PATCH /api/host/{id}` path.
- Managed fields and `known: true` are committed through the same database transaction and existing event model.
- Normal **Save** and the established Known/Unknown quick action remain available.

## Home integration

- Unknown devices on Home expose a compact **Help identify** shortcut.
- The mobile expanded row exposes the same workflow.
- The shortcut opens the shared Host identification helper rather than creating a second identification workflow.
- The existing **Unknown** recognition summary continues to use the shared `Known=0` filter path.

## UX hardening

- Identification aggregate requests are actively cancelled when superseded, closed or when the Host changes.
- Escape stops a running investigation first; when no investigation is running, Escape closes the helper.
- Closing the helper returns keyboard focus to its **Help identify** entry point.
- Loading, error, retry and busy states remain explicit for assistive technology.
- Small-screen controls stack into a readable single-column layout instead of compressing horizontally.

## UAT upgrade path

From **v0.1.0-beta.11**:

1. Open **Settings → Updates**.
2. Use the **Beta** update channel.
3. Select **Check now**.
4. Confirm that **v0.1.0-beta.11.uat.1** is offered as newer.
5. Start the update through the LANnventory updater.
6. After reconnect, confirm the installed version reports **0.1.0-beta.11.uat.1**.

## UAT focus

### Unknown device workflow

- Open an Unknown device and select **Help identify**.
- Confirm that opening the helper performs no automatic active probes.
- Check that retained evidence clearly distinguishes current from stale/historical clues.
- Check suggestions, confidence, provenance, cautions and conflicts.
- Use one or both suggestions and confirm they only populate the managed edit draft.

### Investigation actions

- Run **Refresh names** and confirm the Host Presence/LastSeen state does not change.
- Run one bounded TCP preset and confirm progress/open ports are understandable.
- Stop a running preset and confirm the UI exits cleanly without losing already completed observations.
- Confirm **Services** and **Identity history** shortcuts open the existing Network sections.

### Save flow

- From an Unknown device with staged managed values, use **Save and mark Known**.
- Confirm the values and Known state update together.
- Confirm the identification helper closes after the Known transition.
- Confirm the device no longer appears in the Unknown Home filter.

### Evidence scenarios

Where available, check:
- a Proxmox VM/LXC with an exact interface MAC match;
- a printer-like device;
- a camera/IoT-like device;
- a device with only weak/generic ports;
- stale retained service/discovery evidence;
- conflicting current clues;
- an IP that has been reused historically.

### Home and responsive behavior

- Confirm Unknown rows expose **Help identify** on desktop and mobile.
- Check the workflow around 390–430 px width.
- Confirm there is no horizontal overflow or unusably compressed action layout.
- Confirm keyboard Escape/Stop/Close behavior remains predictable.
