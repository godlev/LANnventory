# LANnventory v0.1.0-beta.9.uat.2

## Summary

This is a focused Phase 35.9 follow-up UAT build based on a real-environment finding from `v0.1.0-beta.9.uat.1`.

- Fixes timezone-aware timestamps being displayed as if their UTC clock time were already local.
- RFC3339 timestamps carrying `Z` or an explicit UTC offset are now converted to the browser's local timezone before rendering.
- Keeps the backend/database representation in UTC; scheduler cadence and stored timestamps are unchanged.
- Preserves the existing behavior for legacy timestamps that do not contain timezone information, avoiding an unintended shift of older local display values.
- Adds a regression check for Europe/Sofia confirming `18:16Z → 21:16` during September daylight-saving time.

All Phase 35.9 scheduled Proxmox API sync functionality from UAT1 remains unchanged.

## UAT focus

Upgrade from `v0.1.0-beta.9.uat.1` through **Settings → Updates** on the **Beta** channel.

On the Proxmox API section verify:

1. Existing API configuration, token, Automatic Sync setting and interval remain intact.
2. **Last attempt**, **Last successful collection**, **Last applied**, and **Next sync** are shown in your browser's local time.
3. In Bulgaria during September, a backend value such as `18:16Z` should display as `21:16`, not `18:16`.
4. **Next sync** should no longer appear to be several hours in the past when the scheduler is actually waiting for a future run.
5. Automatic sync itself should continue on the same cadence; this build changes display conversion only.
6. Manual **Sync now → Preview/Diff → Apply** should remain unchanged.

## Release status

Phase 35.9 follow-up UAT candidate. Do not merge into `main` until real-environment UAT is explicitly approved.
