# LANnventory v0.1.0-beta.3 — release candidate notes

## Highlights

- Refined Home and Events summary cards.
- Added current-Unknown device scope in Events.
- Redesigned Host details actions and adaptive tooltips, including touch long-press support.
- Refined Host details / Port Scan proportions across desktop breakpoints.
- Added open-port activity events when newly discovered open ports are found.
- Added Stable/Beta update channels and one-click update controls in Settings.
- Added verified GitHub release discovery, SHA256 checking and Debian package/architecture validation.
- Added versioned pre-update recovery backups and post-update health validation using the configured LANnventory bind address.
- Hardened release packaging so DEB/RPM/APK artifacts cannot silently ship stale embedded frontend assets.

## Validation required before publication

- Packaging Check green on the final release candidate SHA.
- Release Artifact Dry Run green on the same SHA.
- Backend tests, race detector, vet and build pass.
- Docker build, Compose validation and safe container smoke test pass.
- Generated release artifacts and package contents validate for all expected architectures.
- Existing Phase 29 checkpoint UI remains visually unchanged except for update-progress/recovery messaging.
- Real Proxmox LXC update-path test from the current checkpoint snapshot.

## Suggested real update-path validation

1. Keep the current known-good checkpoint backup on the test LXC.
2. Publish an intermediate prerelease newer than beta.2 but lower than beta.3.
3. Use the existing Update button to move the LXC to that prerelease.
4. Verify data, UI, service and recovery backup.
5. Publish v0.1.0-beta.3.
6. Use the hardened updater from the intermediate prerelease to update to beta.3.
7. Verify service health, version and preserved data again.

## Not yet claimed as fully validated

- PostgreSQL runtime deployment.
- Automatic update installation on RPM/APK/manual-binary/Docker deployments.
- Built-in authentication.
