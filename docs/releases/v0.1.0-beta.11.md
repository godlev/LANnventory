# LANnventory v0.1.0-beta.11

## Summary

LANnventory 0.1.0-beta.11 finalizes **Phase 35.10 — Full Host + Settings UX Review & Redesign** after real-environment UAT through `v0.1.0-beta.10.uat.6`.

The release keeps the Phase 35.10 implementation validated in UAT6 and advances the beta number so the updater correctly treats the finalized release as newer than every `beta.10.uat.x` build.

## Phase 35.10 highlights

### Host workspace

- Reworks the Host page into one coherent Host workspace instead of a long stack of unrelated cards.
- Keeps a compact Device Overview with name, status, device type, IP, MAC, owner and location immediately visible.
- Preserves clear provenance between managed information and current/discovered network state.
- Adds explicit **Inventory / Network / Activity** local navigation.
- Shows only one secondary Host section at a time to materially reduce page length.
- Keeps Proxmox Workloads collapsed by default.
- Uses consistent **Show details / Hide details** progressive disclosure for secondary technical information.
- Preserves Host edit/save/cancel, Wake-on-LAN, Known/Unknown, Pin/Home and destructive overflow actions.
- Keeps Services, Network Identity, Device Profile, Proxmox inventory/matching and Activity/Presence integrated in the Host workflow.
- Uses a structural `.host-workspace` container rather than Bootstrap gutter and negative-margin compensation.

### Settings

- Adds explicit Settings navigation for **General, Network discovery, Diagnostics, Data & retention, Updates, Integrations and About**.
- Separates settings, status and actions more clearly.
- Makes save behavior explicit per section.
- Keeps update preferences immediate while explicit-save settings remain explicit.
- Standardizes safe write-only secret handling for supported integrations.
- Improves desktop, narrow and mobile layout behavior.

### Updater UX and recovery

- Adds durable persisted update-attempt state.
- Reports real backend stages only: **Preparing → Downloading → Verifying → Creating backup → Installing → Restarting → Health check → Complete**.
- Does not invent percentage progress.
- Survives browser refresh and the expected LANnventory restart disconnect.
- Reconciles stale/interrupted attempts instead of leaving the UI permanently stuck.
- Persists backup, failure-stage and recovery information.
- Verifies completion against the actually installed backend version.
- The full updater path, including backup creation, restart, reconnect/resume and health verification, was validated in real-environment UAT.

### Presence history

- Fixes browser-local calendar-day filtering when backend/container timestamps use a different timezone.
- Selected dates are mapped to the correct UTC interval for the browser-local day, including DST boundaries.
- Date changes perform a real refetch.
- Loading, empty and failure states are distinct.
- Presence timestamps and day/night classification remain browser-local.

### Regression protection

- Host UX semantic tests validate structural behavior rather than incidental CSS values.
- Settings UX semantic contracts remain covered.
- Packaging validates the embedded frontend bundle.
- Linux CI covers backend tests, race tests, vet and build.
- Docker packaging and container smoke tests remain part of Packaging Check.
- Release Artifact Dry Run validates distributable packages before publication.

## UAT findings incorporated

Phase 35.10 was validated through six updater-visible UAT builds.

- **UAT1** introduced the Host/Settings redesign, Presence date-boundary fix and durable updater progress/recovery model.
- **UAT2** shortened the Host page with Inventory/Network/Activity navigation and explicit progressive disclosure. The real updater flow was validated end to end.
- **UAT3–UAT5** incorporated direct visual feedback around Host header density, tab integration and alignment.
- **UAT6** replaced the accumulated layout compensation with a structural Host workspace refactor. Final smoke testing confirmed Host section switching, Proxmox disclosure behavior, Edit/Cancel and Presence date switching behaved normally.

## Upgrade path

Beta-channel installations on `v0.1.0-beta.10` or any Phase 35.10 UAT build (`v0.1.0-beta.10.uat.1` through `v0.1.0-beta.10.uat.6`) should converge on `v0.1.0-beta.11`.

The Stable channel continues to exclude beta prereleases.

## Scope

This release completes Phase 35.10 only. It does **not** start the Unknown Device Identification Toolkit or Phase 36 router/network-source integrations.
