# LANnventory v0.1.0-beta.11.uat.3

## Summary

This focused Phase 35.11 follow-up refines the single-message Unknown Device Identification result after real-environment UAT2 feedback.

The one-button identification workflow remains unchanged. UAT3 makes the fallback result more useful when LANnventory cannot confidently classify a device.

## What changed from UAT2

- Keeps the compact **Help identify → Identify device → one result message** workflow.
- Uses the Host's known vendor in an uncertain result when available, for example:
  - **Unknown Dell Inc device.**
- Reports a generic open service without incorrectly turning it into a device classification, for example:
  - **SSH (TCP 22) is available, but no hostname or device-specific service was found, so the device type remains uncertain.**
- When no useful service or hostname is found, explains that directly instead of returning a vague generic failure.
- Quantifies inconclusive service checks instead of saying only that "some checks" were inconclusive.
- Strong exact-MAC workload results are unchanged, for example:
  - **Likely Container (high confidence), name "passbolt" (high confidence).**
- No managed Name, Device Type or Known state is written automatically.

## Security maintenance included

The frontend lockfile was refreshed narrowly after new registry advisories appeared after UAT2:

- `solid-js` 1.9.16
- `seroval` 1.6.8
- `seroval-plugins` 1.6.8
- `source-map-js` 1.2.2

The refresh resolves the newly surfaced critical/high dependency audit findings without a broad frontend dependency upgrade.

## UAT upgrade path

From **v0.1.0-beta.11.uat.2**:

1. Open **Settings → Updates**.
2. Use the **Beta** channel.
3. Select **Check now**.
4. Confirm **v0.1.0-beta.11.uat.3** is offered as newer.
5. Upgrade through the built-in updater.
6. Confirm the installed version reports **0.1.0-beta.11.uat.3**.

## UAT focus

Please recheck only the focused scenarios:

1. Exact-MAC Proxmox VM/LXC identification still returns the strong concise result.
2. A device with only a generic open service such as SSH remains unclassified but the message names the useful service.
3. A device with no distinctive service/hostname uses vendor context when available.
4. Inconclusive port checks are quantified.
5. Identify/Stop/Identify again still behave as one-action workflow.
6. No managed identity field or Known state changes automatically.
