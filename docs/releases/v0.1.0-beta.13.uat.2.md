# LANnventory v0.1.0-beta.13.uat.2

## Summary

Phase 38A — Relationship Foundation second UAT candidate. Builds on `v0.1.0-beta.13.uat.1` and fixes an identified SQLite burst-concurrency failure in manual relationship mutations.

## Changes from UAT1

- Serialize full manual relationship create, note-update and delete operations for the SQLite dialector using a process-local mutex.
- Preserve transactional endpoint validation, unique-index duplicate detection, provenance restrictions, and rollback behavior.
- Do not reinterpret `SQLITE_BUSY` as a duplicate relationship.
- PostgreSQL code path remains unchanged (no SQLite mutex applied).
- Add concurrent API regression test verifying one HTTP 201 and 15 HTTP 409 results for 16 identical creates.
- Add database tests for 2, 16 and 32 concurrent creates, 100 repeated 16-writer bursts, different endpoint pairs, concurrent updates/deletes, and lock-error classification.

## What UAT1 already introduced

- Directed manual Host-to-Host assertions (`connected_to`, `manages`, `depends_on`), their CRUD API and Host Inventory UI.
- Read-only projections of authoritative Proxmox hypervisor/workload ownership and workload-to-Host matches.
- Bounded one-hop canonical relationship graph.
- Logical export format v6 for relationship assertions.

## Known limits

- SQLite mutation serialization is process-local. Multiple processes sharing a single SQLite database file are not protected by this mutex; the supported single-process deployment is the intended configuration.
- Graph relationships do not constitute automatic physical network topology.
- Logical export is not an import/restore facility.
