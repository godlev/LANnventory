# LANnventory v0.1.0-beta.11.uat.2

## Summary

This follow-up UAT build simplifies the **Unknown Device Identification** experience based on real-environment feedback from UAT1.

The identification helper is now intentionally focused on one question: **what is this device?**

Instead of exposing several technical investigation controls, the Host page now presents one guided action and one concise result.

## What changed from UAT1

- Replaces separate **Refresh names**, TCP preset, Services and Identity-history actions with one **Identify device** action.
- Uses the existing safe building blocks behind that single action:
  - retained identification evidence;
  - targeted local-name refresh;
  - one fixed bounded set of common TCP ports.
- The fixed service set is:
  - 22, 80, 443, 445, 515, 554, 631, 8000, 8080, 8443, 8554, 9100.
- The button changes to **Stop** while identification is running and to **Identify again** after a result.
- Results are collapsed into one short message describing:
  - the likely device type when evidence supports one;
  - a possible name when evidence supports one;
  - confidence;
  - the most useful evidence;
  - relevant open services when useful.
- When evidence is insufficient, the result says so directly instead of presenting multiple technical panels.
- The helper no longer exposes source-count badges, suggestion action buttons, preset selectors or investigation shortcuts in the main workflow.
- No probes run automatically when the helper opens.
- No managed Name, Device Type or Known state is saved automatically.
- Escape still stops a running identification first, then closes the helper when idle.
- Existing Host-bound probe safety and stale-binding protection remain unchanged.

## Example result style

A weakly identified device may now produce a single message similar to:

> I couldn't identify this device reliably. I found SSH (TCP 22), but no current hostname or device-specific evidence was strong enough to classify it.

A stronger match may produce a result such as:

> Likely Virtual machine (high confidence), name "ubuntu-plex" (high confidence). Evidence: one current workload interface MAC exactly matches the Host MAC.

## UAT upgrade path

From **v0.1.0-beta.11.uat.1**:

1. Open **Settings → Updates**.
2. Use the **Beta** channel.
3. Select **Check now**.
4. Confirm **v0.1.0-beta.11.uat.2** is offered as newer.
5. Upgrade through the built-in updater.
6. Confirm the installed version reports **0.1.0-beta.11.uat.2**.

## UAT focus

Please validate the simplified workflow on a few different Unknown devices:

1. Open an Unknown Host and select **Help identify**.
2. Confirm the helper is visually compact and does not expose the old collection of investigation buttons.
3. Confirm there is one primary **Identify device** action.
4. Run it and verify that the final result is one concise, understandable message.
5. Test a device where only a generic service such as SSH is found; it should not invent a device type.
6. Where available, test a printer/camera-like device and a Proxmox VM/LXC exact-MAC match.
7. Confirm **Stop** cleanly cancels a running identification.
8. Confirm no managed identity fields or Known state change automatically.
