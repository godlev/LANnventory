# LANnventory v0.1.0-beta.10

## Summary

LANnventory 0.1.0-beta.10 finalizes **Phase 35.9 — Scheduled Proxmox API Sync** after real-environment UAT.

It extends the Phase 35.8 read-only Proxmox API integration with safe per-host scheduled inventory collection while preserving the existing manual Preview/Diff/Apply workflow and all matching, retirement, and last-good-inventory protections.

## Phase 35.9 highlights

- Per-Proxmox-host **Automatic Sync**, disabled by default.
- Supported intervals: **15 minutes, 30 minutes, 1 hour, 6 hours, 12 hours, and 24 hours**.
- One shared sync service for manual and automatic collection.
- Central context-aware scheduler rather than one permanent worker per host.
- Bounded concurrency and same-host run exclusion.
- Clean shutdown and cancellation of in-flight automatic work.
- Live interval/enabled-setting changes without restarting LANnventory.
- Config-revision protection so stale in-flight results cannot overwrite newer configuration.
- Deterministic next-run scheduling without startup sync storms.
- Automatic apply only for complete, valid snapshots that pass existing Phase 35 matching and conflict safety rules.
- **Review required** state when collection succeeds but automatic apply would be unsafe.
- Last-good inventory is preserved on authentication, TLS, timeout, malformed/incomplete snapshot, validation, and blocking-conflict failures.
- Workload retirement remains allowed only from trusted complete snapshots.
- Separate runtime state for **Last attempt**, **Last successful collection**, **Last applied**, **Last error**, **Next sync**, and trigger.
- Compact scheduler controls integrated into the existing Proxmox API section.
- API token secret remains write-only.
- No Proxmox VM/LXC start, stop, reboot, create, delete, or other control operations.

## UAT findings incorporated

Phase 35.9 was validated through three updater-visible UAT builds.

### v0.1.0-beta.9.uat.1

Real-environment testing exposed that RFC3339 UTC timestamps were being rendered using the UTC clock value rather than the browser-local timezone.

The UI formatter was corrected so timestamps with `Z` or an explicit timezone offset are converted to browser-local time while legacy timezone-less display values keep their existing behavior.

### v0.1.0-beta.9.uat.2

Changing the automatic-sync interval could temporarily leave **Next sync** showing `Scheduling…`.

The scheduler itself was already notified correctly, but the configuration PATCH response was returned before the asynchronous scheduler had persisted the new next-run time.

The final implementation now calculates and persists the deterministic next run synchronously as part of the configuration update, using the same scheduling helper as the scheduler. The Save response therefore immediately contains the truthful future **Next sync** value.

### v0.1.0-beta.9.uat.3

The final UAT candidate included both fixes and passed automated validation. UAT was approved before the Phase 35.9 merge to `main`.

## Safety and regression coverage

Automated coverage includes:

- automatic scheduling disabled by default;
- supported interval validation;
- interval changes and deterministic rescheduling;
- no immediate sync merely from enabling scheduling;
- bounded scheduler concurrency;
- same-host manual/automatic exclusion;
- shutdown cancellation and worker cleanup;
- stale config-revision protection;
- authentication, TLS, and timeout failures preserving last-good inventory;
- incomplete/unsafe snapshots not being applied automatically;
- matching/review conflicts preventing automatic apply;
- safe retirement from complete trusted snapshots;
- database restart persistence;
- updater ordering proving `beta.10` supersedes `beta.9.uat.1`, `beta.9.uat.2`, and `beta.9.uat.3`.

## Upgrade path

Beta-channel installations on `v0.1.0-beta.9` or any Phase 35.9 UAT build should converge on `v0.1.0-beta.10`.

Automatic Sync remains **off by default** for existing hosts unless the user explicitly enabled it during Phase 35.9 UAT/configuration.

## Scope

This release completes scheduled read-only Proxmox inventory synchronization only. Proxmox control operations, monitoring, topology, MikroTik/GL.iNet/OpenWrt integrations, and later roadmap work remain outside Phase 35.9.
