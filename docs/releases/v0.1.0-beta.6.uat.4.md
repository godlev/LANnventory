# LANnventory v0.1.0-beta.6.uat.4

## Summary

- Improves the Phase 35A Proxmox collector workflow for larger environments: the generated command now writes compact JSON directly to /tmp/lannventory-proxmox.json instead of flooding the Proxmox terminal.
- Makes file upload the recommended path for larger snapshots and provides an SCP example to copy the snapshot from Proxmox to the user's computer; manual compact JSON paste remains available for smaller setups.
- Removes programmatic clipboard writes for terminal commands. "Copy" is replaced with "Select command", so security extensions that detect ClickFix-style clipboard injection are not triggered by LANnventory.
- Adds an explicit "What Import will do in LANnventory" section to Preview with the actual Add / Update / Retire counts.
- Clarifies that workloads remain separate inventory records and are not turned into fake LANnventory Hosts.
- Clarifies that Import never creates, modifies, starts, stops, or deletes VMs/LXCs on Proxmox.
- Clarifies that managed Device Profile fields and manual workload links remain protected.
- Renames the final action from the ambiguous "Apply reviewed snapshot" to "Import into LANnventory".

## UAT focus

Upgrade from v0.1.0-beta.6.uat.3 through Settings → Updates on the Beta channel.

Verify:
- the collector command creates /tmp/lannventory-proxmox.json without dumping the full JSON into the shell;
- "Select command" only selects text and does not write terminal commands to the clipboard automatically;
- the SCP example uses the current Proxmox Host address and the JSON file can be uploaded with "Choose JSON file";
- manual paste of compact JSON still works as a fallback;
- Preview clearly explains what Import will change in LANnventory before confirmation;
- the Preview explicitly says that Proxmox itself will not be modified and no fake Hosts will be created;
- the final button reads "Import into LANnventory";
- the UAT3 duplicate-interface collector fix remains intact.
