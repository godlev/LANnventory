# LANnventory v0.1.0-beta.6.uat.5

## Summary

- Adds a first-class **Possible IP conflict** state for Proxmox workload suggestions where the imported workload IP matches a LANnventory Host but their known MAC addresses differ.
- Shows the Proxmox workload and LANnventory Host side by side with IP/MAC evidence so reused addresses are not mistaken for the same device.
- Adds explicit weak-match actions: **Link anyway** for a deliberate manual relationship and **Not this Host** to reject a wrong suggestion without changing Host identity or history.
- Persists rejected weak suggestions while their material identity evidence is unchanged. Timestamp refreshes, online/offline changes, and current-vs-history address observations for the same IP no longer make a rejected suggestion reappear.
- Re-evaluates a rejected suggestion when material evidence changes, such as the Host/workload MAC or matching IP. A later deterministic exact-MAC match supersedes the weak rejection.
- Makes the reverse Proxmox relationship visible on linked guest Hosts: the Host page shows **Hosted on Proxmox**, and the Home table shows the VM/LXC parent relationship for active workload memberships.
- Keeps manual workload links protected and preserves the Phase 35 safety model: LANnventory does not create, modify, start, stop, or delete anything on Proxmox.

## UAT focus

Upgrade from v0.1.0-beta.6.uat.4 through Settings → Updates on the Beta channel.

Verify:
- CT/VM candidates with the same IP but a different known MAC are labeled **Possible IP conflict** rather than presented as an ordinary match;
- the comparison shows both sides' name/IP/MAC and clearly calls out the address-only evidence and MAC difference;
- **Not this Host** persists after another import when only observation timestamps or online/offline state changed;
- a changed IP or MAC causes the candidate to be reconsidered instead of permanently suppressing it;
- an exact MAC match remains the only deterministic automatic link path and can supersede a prior weak rejection;
- **Link anyway** creates only the intended manual workload ↔ Host relationship and does not merge Host identity/history;
- a linked guest Host shows **Hosted on Proxmox** on its Host page;
- the Home table shows the VM/LXC parent indicator for active linked workloads;
- retired workload memberships do not create misleading active parent badges on Home;
- the UAT4 collector/upload/preview safety workflow remains intact.
