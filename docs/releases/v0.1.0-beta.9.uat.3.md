# LANnventory v0.1.0-beta.9.uat.3

## Summary

This is a focused Phase 35.9 follow-up UAT build based on a real-environment scheduling display finding from `v0.1.0-beta.9.uat.2`.

- Fixes **Next sync** remaining on `Scheduling…` after changing the Automatic Sync interval and saving.
- The API config PATCH now calculates and persists the deterministic next scheduled run before returning the response.
- The API and central scheduler use the same shared next-run calculation, so the UI receives the same schedule that the scheduler will honor.
- Changing the interval immediately returns a real future `NextSyncAt`; no manual Sync now or page refresh is required to reveal it.
- A no-op Save preserves the existing next scheduled run instead of moving the cadence.
- Automatic Sync still does **not** run immediately when enabled or when the interval changes; the first run remains scheduled after the selected interval plus the existing deterministic startup spread.
- Keeps the timezone-aware display fix from UAT2: RFC3339 UTC/offset timestamps are rendered in the browser's local timezone.

All Proxmox collection, Preview/Diff, safety gate, retirement, matching, and manual sync behavior remain unchanged.

## UAT focus

Upgrade from `v0.1.0-beta.9.uat.2` through **Settings → Updates** on the **Beta** channel.

On the Proxmox API section verify:

1. Existing API configuration, token, Automatic Sync state and interval remain intact.
2. Change the Automatic Sync interval, for example from **Every 1 hour** to **Every 30 minutes**, and press **Save**.
3. **Next sync** should immediately show a concrete local date/time instead of remaining on `Scheduling…`.
4. The displayed next time should be in the future and approximately one selected interval away; a small deterministic spread is expected.
5. Change the interval again and verify **Next sync** changes immediately to the new cadence.
6. Press **Save** again without changing settings and verify the current **Next sync** time is preserved.
7. Do not use **Sync now** for this check; the schedule must become visible from Save alone.
8. If convenient, let one scheduled run occur and verify **Last attempt**, **Last successful collection**, **Last applied**, and the next scheduled time advance normally.

## Release status

Phase 35.9 follow-up UAT candidate. Do not merge into `main` until real-environment UAT is explicitly approved.
