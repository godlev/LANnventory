# LANnventory v0.1.0-beta.13.uat.1

## Summary

UAT candidate for **Phase 38A — Relationship Foundation**, based on v0.1.0-beta.12. This adds explicit manual Host relationships and read-only projections of existing Proxmox infrastructure relationships. It does **not** introduce a visual topology map, inferred physical links, or automatic network relationship discovery.

## Changes

- Persistent, directed manual Host-to-Host relationships: `connected_to`, `manages`, `depends_on`.
- Strict manual API: relationship types, current-Host search, create, list, note-only edit, delete.
- Reject duplicate/self relationships, invalid endpoints, unsupported types and attempts to edit source-owned records.
- Read-only canonical one-hop graph from manual claims, Proxmox hypervisor/workload ownership and existing workload-to-Host matches.
- Explicit provenance, direction, source details and VM/LXC identifiers without inventing LAN Hosts.
- Minimal **Host → Inventory → Relationships** UI; scoped, bounded graph reads and guarded edits.
- Relationship schema migration and logical backup format v6. Historical v5 exports remain decodable.
- Regression coverage for scoped graph limits, deletion, persistence across database reopen, migration repeatability and transactional cleanup.
- Refresh vulnerable frontend dependency lockfile; security audit clean at commit a4ae0a2.

## Limits and safety

- `connected_to` is a user-declared relationship, **not** proof of a physical port or cable.
- Source-owned Proxmox relationships cannot be edited using the manual relationship UI.
- No logical backup restore importer is provided; make and verify a complete Proxmox CT129 backup before upgrading.
- Phase 35.12 UI redesign stays paused. No merge to `main`.
