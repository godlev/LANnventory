# LANnventory v0.1.0-beta.12

## Summary

LANnventory 0.1.0-beta.12 finalizes **Phase 35.11 — Unknown Device Identification Toolkit** after real-environment UAT through `v0.1.0-beta.11.uat.3`.

The release adds a conservative, explainable workflow for turning Unknown hosts into useful identification candidates without automatic classification, arbitrary network scanning, or hidden writes.

## Phase 35.11 highlights

### Retained identification evidence

- Adds `GET /api/host/{id}/identification` as the aggregate retained-evidence view for an Unknown Host.
- Separates current evidence from stale or historical evidence so old addresses and services are not presented as current facts.
- Combines current Host identity, retained discovery clues, services, address history and Proxmox workload evidence.
- Surfaces warnings and conflicts instead of forcing a classification when evidence disagrees.

### Explainable suggestions

- Uses conservative suggestion rules for device type and name.
- Treats an exact current Proxmox workload-interface MAC match as high-confidence VM/container evidence.
- Keeps generic SSH or web services as clues only; they do not invent a device type.
- Prioritizes stronger current evidence such as exact workload identity and meaningful local hostnames over weaker generic clues.
- Avoids double-counting reverse DNS and system-resolver results when they resolve to the same hostname.

### One-action identification UX

- Adds a compact **Help identify** workflow to Unknown Host pages.
- Uses one primary action: **Identify device** / **Stop** / **Identify again**.
- Opening the helper does not automatically probe the network.
- The explicit Identify action performs only bounded Host-scoped checks: targeted local-name refresh plus a fixed common-service TCP set.
- Returns one concise result message instead of exposing a mini-toolbox of scan presets and evidence buttons.
- Keeps the result conservative when evidence is insufficient and explains what useful clue was or was not found.
- UAT3 improves fallback messages with known vendor context, generic-service reporting and quantified inconclusive checks.

### Safe active investigation

- Active checks remain bound to the selected Host and current canonical address.
- Probe persistence revalidates Host existence, Host ID, canonical MAC and canonical IP relation before retained evidence is written.
- Stale bindings are rejected rather than attached to the wrong Host.
- Targeted hostname refresh does not alter Presence, Date/Now or LastSeen.
- The workflow does not perform arbitrary address scanning or cloud fingerprinting.

### Known transition

- Reuses the existing atomic Host PATCH path for managed identity changes.
- Adds explicit **Save and mark Known** behavior so staged managed fields and the Known transition are persisted together.
- Identification itself never automatically writes Name, Device Type or Known state.
- Home Unknown rows link into the same Host identification workflow rather than creating a second path.

### UX, cancellation and regression protection

- Investigation and aggregate loading are cancellable with `AbortController`.
- Escape stops an active investigation before closing the helper.
- Keyboard focus returns to the Identify entry point after close.
- The helper exposes busy/live-status semantics and remains compact on narrow/mobile layouts.
- Host semantic regression tests lock the one-action workflow, no-auto-probe behavior, no-direct-save rule and Home integration.

## UAT findings incorporated

Phase 35.11 was validated through three updater-visible UAT builds.

- **UAT1** exposed the full retained-evidence and investigation toolkit. Real usage showed that the interface was too text-heavy and action-heavy.
- **UAT2** replaced the toolbox with a single guided Identify action and one concise result message. Exact-MAC Proxmox container identification was confirmed in the real environment, while uncertain devices remained conservatively unclassified.
- **UAT3** refined uncertain fallback results to include useful vendor/service context and quantified inconclusive checks without weakening the conservative classification rules.

## Dependency security maintenance

During UAT3 preparation, the frontend audit surfaced new upstream advisories. The lockfile was narrowly refreshed to patched dependency lines, including `solid-js` 1.9.16, `seroval` 1.6.8, `seroval-plugins` 1.6.8 and `source-map-js` 1.2.2. The final candidate passes the frontend dependency audit.

## Upgrade path

Beta-channel installations on `v0.1.0-beta.11` or any Phase 35.11 UAT build (`v0.1.0-beta.11.uat.1` through `v0.1.0-beta.11.uat.3`) should converge on `v0.1.0-beta.12`.

The Stable channel continues to exclude beta prereleases.

## Scope

This release completes Phase 35.11 only. It does **not** start Phase 36 router/network-source integrations.
