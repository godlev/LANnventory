# LANnventory v0.1.0-beta.10.uat.2

## Summary

This is a focused Phase 35.10 follow-up UAT build based on direct real-environment feedback from `v0.1.0-beta.10.uat.1`.

UAT1 confirmed that the Settings redesign and upgraded runtime were healthy, but the Host page still felt too long and its expandable areas did not clearly look interactive. UAT2 addresses those two findings without changing the underlying Host, Proxmox, Services, Identity, Presence, or updater data models.

### Host page structure

- Keeps **Device Overview** permanently visible at the top.
- Replaces the long stack of secondary cards with three explicit local sections:
  - **Inventory** — Hosted workload relationships, Device Profile, Proxmox inventory.
  - **Network** — Services and Network Identity.
  - **Activity** — Recent Events and Presence History.
- Only the selected section is displayed, substantially reducing vertical page length.
- The selected Host section has a clear active state and remains keyboard-focusable.

### Progressive disclosure

- Makes secondary expandable areas visibly interactive instead of relying on the browser's hidden native details marker.
- Adds a consistent **Show details ▾ / Hide details ▴** affordance with hover and focus states.
- Applies the shared disclosure treatment to:
  - Proxmox workloads.
  - Proxmox connection and collection.
  - Proxmox source details.
  - Rejected workload match suggestions.
  - Manual service scan.
  - Historical services.
  - Scheduled service scanning.
  - Identity history.
  - Presence history.
- **Proxmox Workloads** is collapsed by default so a host with many VMs/LXCs no longer expands the page by several screens unless the user asks to see the workload table.

### Regression protection

- Adds Host UX contract checks requiring the local Inventory/Network/Activity navigation.
- Requires non-selected Host sections to remain hidden.
- Requires large Proxmox workload inventory to remain behind progressive disclosure.
- Requires a visible Show/Hide affordance whenever the native details marker is hidden.
- Embedded frontend assets were rebuilt and validated by the normal packaging pipeline.

## UAT upgrade path

Upgrade from **v0.1.0-beta.10.uat.1** using:

1. **Settings → Updates**
2. Update channel: **Beta**
3. **Check now**
4. Confirm that **v0.1.0-beta.10.uat.2** is offered.
5. Start the update through the LANnventory updater.

For this update, pay particular attention to the new updater progress/reconnect experience that was not observed during UAT1. The expected stages are:

**Preparing → Downloading → Verifying → Creating backup → Installing → Restarting LANnventory → Verifying health → Complete**

A temporary disconnect during restart is expected. The page should reconnect/resume and finish with the actually installed version confirmed.

## UAT focus after upgrade

### Host navigation

- Device Overview remains visible regardless of selected Host section.
- Inventory, Network and Activity are clearly discoverable and switch immediately.
- Only one secondary section is visible at a time.
- Switching sections does not lose managed data or break controls.

### Proxmox

- Workloads are collapsed initially and the total count remains visible.
- Expanding Workloads shows the existing VM/LXC table and matching controls.
- Connection & collection, Source details and rejected suggestions clearly indicate that they can be expanded.
- Manual sync, Automatic Sync, matching, link/unlink and read-only inventory behavior remain unchanged.

### Services / Identity / Presence

- Manual scan, historical services and scheduled scanning have an obvious Show/Hide affordance.
- Identity history has an obvious Show/Hide affordance.
- Presence history has an obvious Show/Hide affordance and the browser-local day/timezone fix from UAT1 remains intact.

### Updater

- Observe each real update stage.
- Verify the restart disconnect is handled as expected.
- Verify automatic reconnect/resume.
- Verify completion reports **0.1.0-beta.10.uat.2** and LANnventory returns healthy.

## Release status

Phase 35.10 follow-up UAT candidate. Do not merge into `main` until real-environment UAT is explicitly approved.
