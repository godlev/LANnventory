# LANnventory v0.1.0-beta.8.uat.1

## Summary

- Adds an optional **read-only Proxmox API** inventory source beside the existing manual/script collector workflow.
- Adds per-Proxmox-host API configuration with HTTPS-only endpoints, dedicated API Token ID/secret authentication, bounded request timeouts and TLS certificate verification enabled by default.
- Keeps the API token secret write-only: LANnventory never returns it through configuration APIs and excludes it from backup exports and user-facing error details.
- Adds **Test connection** to verify authentication plus node, VM and LXC read access without changing LANnventory inventory.
- Adds **Sync now → Preview/Diff → explicit Apply** using the same canonical Proxmox Snapshot contract, matching rules and atomic workload persistence already used by the script collector.
- Adds Proxmox cluster/node provenance so imported VM/LXC workloads retain their owning node while remaining normal LANnventory infrastructure workload records.
- Supports safe transition between script-import and API provenance without creating duplicate workloads or overwriting manual workload links.
- The API source is not enabled by saving credentials. The first successful reviewed **Apply** enables it; it can later be disabled while keeping the stored credentials.
- Authentication, TLS, timeout, malformed-response and partial-collection failures preserve the last good inventory and cannot silently retire missing workloads.

## Security model

- The integration performs GET-only Proxmox API calls for version, cluster/node status, cluster resources and the allowlisted VM/LXC configuration needed for inventory/network identity.
- No start, stop, reboot, create, delete, snapshot, networking, storage or other Proxmox control operations are implemented.
- HTTPS is required. TLS certificate verification is on by default and can only be disabled explicitly with a visible warning.
- Redirects are not followed with API credentials.
- API responses and request timeouts are bounded.
- A dedicated privilege-separated read-only token is recommended. The Proxmox documentation in `proxmox/README.md` includes a least-privilege setup example using `Sys.Audit` + `VM.Audit`.
- Phase 35.8 does **not** add periodic scheduling. Scheduled synchronization remains Phase 35.9.

## UAT focus

Upgrade from `v0.1.0-beta.7` through **Settings → Updates** on the **Beta** channel.

Verify on a real Proxmox VE host:
- the Proxmox Host page still offers the existing **Manual / script** workflow unchanged;
- switching to **Proxmox API** shows Base URL, Token ID, write-only Token Secret, TLS verification and timeout controls;
- saving credentials does not enable or import inventory;
- **Test connection** verifies access but does not change workloads;
- the first **Sync now** shows a complete Preview/Diff before any write;
- cancelling/rejecting Apply leaves current inventory unchanged and the API source disabled;
- confirming Apply imports the reviewed inventory and enables the API source;
- VM/LXC IDs, names, running/stopped state, node ownership and allowlisted network identity match Proxmox;
- existing exact-MAC links and manual links remain correct;
- ambiguous/IP-conflict cases keep the Phase 35 review behavior;
- disabling the API source keeps the saved credentials;
- a bad token, unavailable Proxmox host, TLS validation failure or incomplete guest configuration does not remove or retire the last good inventory.
