# LANnventory v0.1.0-beta.8

## Summary

LANnventory 0.1.0-beta.8 adds an optional **read-only Proxmox API inventory source** alongside the existing Manual / script workflow.

The new integration uses the same canonical Proxmox Snapshot, Preview/Diff, matching, linking and atomic Apply pipeline already used by script imports. It does not add Proxmox control operations and does not add scheduled synchronization.

## Proxmox API inventory

- Per-Proxmox-host API configuration with HTTPS-only Base URL, API Token ID, write-only Token Secret, TLS verification and bounded timeout.
- Dedicated **Test connection** action verifies authentication plus node, VM and LXC read access without changing LANnventory inventory.
- **Sync now → Preview/Diff → explicit Apply** remains mandatory before inventory changes are written.
- Saving credentials alone does not enable the API source. The first successful reviewed Apply enables it.
- The API source can be disabled while retaining stored credentials.
- Explicitly clearing the token secret disables the source.
- VM/LXC workloads retain Proxmox node provenance.
- Existing exact-MAC links and manual workload links are preserved.
- No fake LANnventory Hosts are created for workloads.
- Only exact, unambiguous MAC matches may auto-link; weaker evidence remains review-only.

## Reconciliation safety

- Complete API snapshots are authoritative across the managed Proxmox inventory scope.
- Script → API migration can retire genuinely missing previously imported workloads while preserving their history.
- Node-local script imports do **not** retire API-managed workloads that may belong to another Proxmox cluster node.
- Incomplete API collection cannot be applied destructively.
- Authentication, TLS, timeout, malformed-response and partial-collection failures preserve the last good inventory.
- Repeated unchanged API syncs are idempotent.

## Security

- Proxmox API integration performs GET-only requests for version, cluster/node status, cluster resources and allowlisted VM/LXC configuration required for inventory/network identity.
- No start, stop, reboot, create, delete, snapshot, storage, networking or other Proxmox control calls are implemented.
- HTTPS is required.
- TLS certificate verification is enabled by default.
- Redirects are not followed with API credentials.
- API responses and request timeouts are bounded.
- Token secrets are write-only, excluded from logical backup exports and not returned through configuration APIs.
- Database logging uses parameterized SQL so token values are not rendered into SQL logs.
- A dedicated privilege-separated token is recommended; real-environment UAT validated the current inventory calls with `Sys.Audit` + `VM.Audit`.

## UAT validation

Phase 35.8 was validated against a real Proxmox VE 9.2.20 host through `v0.1.0-beta.8.uat.1` and `v0.1.0-beta.8.uat.2`.

Validated behavior includes:

- TLS fail-closed behavior for an untrusted Proxmox certificate.
- Trusted Proxmox CA with TLS verification remaining enabled.
- Non-mutating Test Connection.
- First Sync producing Preview/Diff before any write.
- Reviewed Apply transitioning existing script-import workloads to API provenance.
- Existing exact-MAC links remaining intact.
- A genuinely removed LXC being retired rather than deleted.
- Repeated unchanged sync producing `0 Add / 0 Update / 31 Unchanged / 0 Retire / 0 Conflicts` in the single-node UAT environment.
- Authentication failure preserving last-good inventory and the previous successful-sync timestamp.
- Clean recovery after credentials are restored.
- Equivalent PVE version forms such as `9.2.20` and `pve-manager/9.2.20` no longer producing a false managed/imported warning.
- API → node-local script cross-source retirement protection covered by automated regression tests.

## Scope

Phase 35.8 is intentionally **manual Sync now only**.

Periodic or scheduled Proxmox API synchronization remains deferred to Phase 35.9.
