# LANnventory v0.1.0-beta.13.uat.3

## Summary

Phase 38A — Relationship Foundation third UAT candidate. Builds on UAT2 (including SQLite concurrent relationship write hardening) and fixes the updater UI remaining on "Update scheduled" after a successful application restart.

## Changes from UAT2

- Use an update `attemptId` in the scheduling response and progress watcher instead of comparing backend `startedAt` with browser `Date.now()`.
- Preserve compatibility with older backends without a scheduling response `attemptId`.
- Continue polling through temporary network unavailability and application restart; prevent overlapping polls and duplicate update submissions.
- Distinguish actual HTTP errors from temporary network failures; resume on dialog reopening.
- Disable cache for update status, progress and version queries.
- Add mocked update-flow regressions for clock skew, scheduled/running/completed transitions, reconnect, restart, failed and lost scheduling responses, cleanup and duplicate prevention.
- Keep existing checksum verification, recovery/rollback, and protected update workflow intact.

## Earlier UAT functionality

- Phase 38A directed manual Host relationship CRUD, graph API and Host UI.
- Proxmox read-only hypervisor/workload and workload-to-Host relationship projections.
- SQLite process-local serialized relationship create/update/delete for single-process installations, with contention regression tests.

## Important UAT behavior

The browser bundle loaded *before* installing UAT3 cannot contain this fix: the UAT2 → UAT3 update may still require a **one-time manual browser refresh**. Verify the fix during a **subsequent** update or controlled mocked end-to-end session running the new bundle. Never claim the bug is corrected based on the installation of UAT3 alone.
