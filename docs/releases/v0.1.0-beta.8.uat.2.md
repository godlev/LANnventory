# LANnventory v0.1.0-beta.8.uat.2

## Summary

This is a focused Phase 35.8 follow-up UAT build based on findings from real Proxmox API testing of `v0.1.0-beta.8.uat.1`.

- Hardens reconciliation when switching between Proxmox API and the node-local script collector.
- Prevents a node-local script import from retiring API-managed workloads that may belong to another Proxmox cluster node.
- Keeps Proxmox API snapshots authoritative across the managed Proxmox scope, so script → API migration can still retire genuinely missing workloads.
- Removes the false managed/imported version warning when the values differ only by the `pve-manager/` prefix, for example `9.2.20` vs `pve-manager/9.2.20`.
- Adds regression coverage for both reconciliation directions and the version-normalization case.

## UAT findings already validated in v0.1.0-beta.8.uat.1

Real-environment UAT confirmed:

- TLS verification fails closed for an untrusted Proxmox certificate.
- Proxmox CA trust can be added while keeping TLS verification enabled.
- A dedicated privilege-separated token with `Sys.Audit` + `VM.Audit` is sufficient for the current inventory calls.
- Test Connection is non-mutating.
- First API Sync produces Preview/Diff before any write.
- Reviewed Apply transitions existing script-import workloads to API provenance without duplicating workloads or losing existing exact-MAC links.
- A genuinely removed LXC is retired rather than deleted.
- Repeated API Sync is idempotent.
- Authentication failure preserves the last successful inventory and successful-sync timestamp.
- Restoring valid credentials recovers cleanly with an unchanged preview.

## UAT focus

Upgrade from `v0.1.0-beta.8.uat.1` through **Settings → Updates** on the **Beta** channel.

Verify:

- existing Proxmox API configuration and stored token remain intact after upgrade;
- **Test connection** remains Connected with TLS verification on;
- **Sync now** on an unchanged Proxmox returns `0 Add / 0 Update / 31 Unchanged / 0 Retire / 0 Conflicts` in the current single-node test environment;
- the previous false version warning for `9.2.20` vs `pve-manager/9.2.20` is gone;
- existing workload links and retired workload history remain unchanged.

The new cross-source retirement protection is covered by automated regression tests because reproducing a multi-node API → node-local script transition is not required on the current single-node UAT host.
