# LANnventory v0.1.0-beta.6.uat.6

## Summary

- Makes persisted workload relationships unmistakable: exact-MAC links now show **Linked automatically**, manual links show **Linked manually**, and the action is renamed from the ambiguous **Unlink** to **Remove link**.
- Reworks the Proxmox workload table proportions so the LANnventory match area has substantially more room.
- Moves IP-conflict actions below the comparison instead of squeezing them beside it, and keeps IP/MAC values from breaking character-by-character.
- Tightens IP reuse semantics: retained/inactive address history is no longer treated as workload matching evidence.
- **Possible IP conflict** now represents a current address overlap with contradictory MAC identity, not merely an IP that another device used in the past.
- Historical address reuse remains available in LANnventory Host identity/history for investigation, but it does not create a stale workload candidate.
- Adds in-context guidance explaining that changing a VM/LXC IP in Proxmox and importing a fresh snapshot removes the conflict once the current addresses no longer overlap.

## UAT focus

Upgrade from v0.1.0-beta.6.uat.5 through Settings → Updates on the Beta channel.

Verify:
- an exact-MAC linked workload clearly says **Linked automatically** and offers **Remove link**;
- a manually chosen relationship clearly says **Linked manually**;
- the Frigate/KIVI-style conflict card is readable at normal desktop width and IP/MAC values do not wrap one character per line;
- **Link anyway** and **Not this Host** appear below the conflict comparison instead of consuming its horizontal space;
- while a workload and LANnventory Host currently share the same IP with different MACs, the row remains **Possible IP conflict** and never auto-links;
- after changing the VM/LXC to a different IP in Proxmox, collecting a new snapshot and importing it, the old IP conflict disappears;
- the other physical device can keep the old IP unchanged;
- the old shared-IP observation remains visible in Host identity/history, but does not come back as a workload candidate by itself;
- exact MAC remains the only deterministic automatic workload-to-Host match.
